# Concurrency

> [!CITE]
>
> Rust as a language doesn’t really have an opinion on how to do concurrency or parallelism. [^nomicon]
>
> lower-level languages are expected to provide the solution with the best performance in any given situation and have fewer abstractions over the hardware. [^book]

## Threads

An executing Rust program consists of a collection of native OS threads, each with their own stack and local state.

Threads can be named, and provide some built-in support for [[low-level synchronization]].

> [!EXAMPLE] Spawning a detached thread
> ```rust
> use std::thread;
> 
> thread::spawn(move || {
>     // some work here
> });
> ```

> [!EXAMPLE] Joining a detached thread
> ```rust
> use std::thread;
> 
> let join_handle: thread::JoinHandle<_> = thread::spawn(move || {
>     // some work here
> });
> // some other work here
> let res: thread::Result<_> = thread_join_handle.join() 
> ```

> [!EXAMPLE] Configuring threads
> A new thread can be configured before it is spawned via the Builder type, which currently allows you to set the name and stack size for the thread:
> ```rust
> let builder = thread::Builder::new()
>                               .name("foo".into())
>                               .stack_size(32 * 1024);
> 
> let handler = builder.spawn(|| {
>     // thread code
> }).unwrap();
> 
> handler.join().unwrap();
> ```

## Thread Safeity

Rust uses two special traits to keep track of which types can be safely used across threads:

### `Send` trait

The Send trait indicates that a value of this type is safe to send from one thread to another.

- auto trait
- dyn compatible

### `Sync` trait

The Sync trait indicates that a value of this type is safe to share between multiple threads.

- auto trait
- dyn compatible
