# Dynamic dispatch

Dispatch is the mechanism to determine which specific version of code is actually run when it involves [[polymorphism]].

Two major forms of dispatch are static dispatch and dynamic dispatch.

The code that results from [[monomorphization]] is doing static dispatch

Rust supports dynamic dispatch through the use of trait objects.

## Trait Object

A *trait object* is an opaque value of another type that implements a set of traits.

The set of traits is made up of a dyn compatible base trait plus any number of [[2. traits#Auto traits|auto traits]].

Trait objects implement the base trait, its auto traits, and any [[2. traits#Supertraits|supertraits]] of the base trait.

There must be at least one trait bound, there may not be more than one non-auto trait, no more than one lifetime, and opt-out bounds (e.g., ?Sized) and [[12. generics#Use bounds|use<..> bounds]] are not allowed.

> [!EXAMPLE] given a trait Trait, the following are all trait objects:
> ```rust
> dyn Trait
> dyn Trait + Send
> dyn Trait + Send + Sync
> dyn Trait + 'static
> dyn Trait + Send + 'static
> dyn Trait +
> dyn 'static + Trait.
> dyn (Trait)
> ```

## Dyn-compatible trait

A trait is dyn compatible if it has the following qualities:

```rust
// Examples of dyn-incompatible traits.
trait TraitWithSize where Self: Sized {} // `Self: Sized` traits are dyn-incompatible.
trait DynIncompatible {
    const CONST: i32 = 1;  // ERROR: cannot have associated const
    fn typed<T>(&self, x: T) {} // ERROR: has generic type parameters

    fn foo() {}  // ERROR: associated function without Sized
    fn returns(&self) -> Self; // ERROR: Self in return type
    fn nested(self: Rc<Box<Self>>) {} // ERROR: nested receiver cannot be dispatched on
}
```
- All supertraits must also be dyn compatible.
- [[3. types#^Sized|Sized]] must not be a supertrait. In other words, it must not require Self: Sized.
- It must not have any associated constants.
- It must not have any associated types with generics.
- All associated functions must either be dispatchable from a trait object or be explicitly non-dispatchable:
    - Dispatchable functions must:
        ```rust
        // Examples of dyn compatible methods.
        trait TraitMethods {
            fn with_lifetime<'a>(self: &'a Self) {}
            fn by_ref(self: &Self) {}
            fn by_ref_mut(self: &mut Self) {}
            fn by_box(self: Box<Self>) {}
            fn by_rc(self: Rc<Self>) {}
            fn by_arc(self: Arc<Self>) {}
            fn by_pin(self: Pin<&Self>) {}
            fn nested_pin(self: Pin<Arc<Self>>) {}
        }
        ```
        - Not have any type parameters (although lifetime parameters are allowed).
        - Be a method that does not use Self except in the type of the receiver.
        - Have a receiver with one of the following types:
            - &Self (i.e. &self)
            - &mut Self (i.e &mut self)
            - Box<Self>
            - Rc<Self>
            - Arc<Self>
            - Pin<P> where P is one of the types above
        - Not have an opaque return type; that is,
            - Not be an async fn (which has a hidden Future type).
            - Not have a return position impl Trait type (fn example(&self) -> impl Trait).
        - Not have a where Self: Sized bound (receiver type of Self (i.e. self) implies this).
    - Explicitly non-dispatchable functions require:
        ```rust
        // This trait is dyn compatible, but these methods cannot be dispatched on a trait object.
        trait NonDispatchable {
            // Non-methods cannot be dispatched.
            fn foo() where Self: Sized {}
            // Self type isn't known until runtime.
            fn returns(&self) -> Self where Self: Sized;
            // `other` may be a different concrete type of the receiver.
            fn param(&self, other: Self) where Self: Sized {}
            // Generics are not compatible with vtables.
            fn typed<T>(&self, x: T) where Self: Sized {}
        }
        ```
        - Have a where Self: Sized bound (receiver type of Self (i.e. self) implies this).
